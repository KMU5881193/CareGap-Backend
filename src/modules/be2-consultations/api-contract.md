# BE2 API 입출력 초안

이 문서는 라우트를 열기 전에 검증할 JSON 형태다. 경로, 예약 상태 이름, 변경·취소 규칙의 확정 계약이 아니다. 공통 계약은 `docs/contracts.md`가 우선한다.

스키마는 `api-schema.ts`에 있다. Express 라우트, DB, 인증 미들웨어는 이 단계에 없다.

## 누가 넣는 값인가

BE1 인증 결과가 넣는 값: 요청자의 `user_id`, `role`. `role: 'staff'`는 그 계정이 상담사라는 뜻이다. 예약 요청자와 담당 상담사는 다른 사용자일 수 있다. 인증된 `user_id`를 담당 상담사로 단정하지 않는다. 승인, 배정, 가족 연결도 BE1이 검사한다.

클라이언트가 넣는 값: 상담 대상 `person_id`, 시간. 요청 본문에 `user_id`, `staff_id`, `role`, `status`를 두지 않는다. 이 스키마에 그 필드가 있으면 알 수 없는 필드로 거절된다. 이것은 인증 주체와 담당 상담사를 본문에서 받지 않는다는 초안이지, 관리자가 다른 상담사 일정을 바꿀 수 있는지를 정한 것이 아니다.

## 입력

가능 시간 본문: `windows[]`의 `start_local`/`end_local`, `exceptions[]`의 `starts_at`/`ends_at`. 둘 다 생략할 수 있다. 필드가 없는 빈 객체 `{}`도 현재 스키마는 통과시킨다. 그 본문이 전체 일정 삭제인지, 거절해야 하는지는 정하지 않았다. 시각은 기존 `ClockTime`과 `UtcInstant`다. 같은 날 시각과 UTC 구간은 종료가 시작보다 뒤여야 한다. 요일, 예외 종류, 자정 넘김 저장은 필드가 없다.

예약 생성 본문: `person_id`, `starts_at`, `ends_at`. 상태 이름은 클라이언트가 고르지 않는다.

예약 식별자: `appointment_id` UUID. 대소문자는 유지한다.

일정 조회: `person_id`, `from`, `to`, `cursor`, `limit`은 모두 선택이다. `limit`은 1 이상의 정수다. 상한은 없다. `from`과 `to`가 같이 있으면 UTC 순서를 검사한다. `person_id`가 있다고 해서 조회 권한이 생긴 것은 아니다.

## 출력

성공은 `{ data }`, 실패는 `{ error: { code, message } }`다. `code`는 공통 계약의 여섯 값만 받는다.

가능 시간 출력은 입력과 같은 시간 필드다.

예약 출력은 `appointment_id`, `person_id`, `starts_at`, `ends_at`, `status`다. `status`는 빈 문자열이 아닌 문자열이다. 허용 상태 목록은 아니다.

## 기존 도메인과의 연결

파싱된 `starts_at`/`ends_at`/`person_id`는 `findAppointmentConflicts`에 넣을 수 있다. `staff_user_id` 인자는 담당 상담사로 이미 결정된 `user_id`다. 그 값은 예약 요청자의 인증 `user_id`와 다를 수 있고, 이 스키마가 요청자로부터 만들어 내지 않는다. 점유 상태와 차단 관계는 여전히 호출자가 고른다.

`applyTransition`의 현재 상태는 이 요청 스키마에서 오지 않는다. 규칙 표도 이 스키마에 없다.

## 미확정

- 담당 상담사를 정하는 방법. 경로, 슬롯 참조, 그 밖의 선택 방식은 아직 없다
- HTTP 경로와 메서드
- `AvailabilityWriteInput`의 빈 객체 `{}`. 통과는 현재 초안의 검증 결과이고, 전체 일정 삭제로 확정하지 않는다
- 예약 상태 이름과 전이 표
- 변경 제안, 취소 시한, 불참 주체, 완료 코멘트 필수 여부
- `meets`를 충돌로 볼지, 어떤 상태가 시간을 점유하는지
- 요일 번호, 시간대 저장, 예외 우선순위, 자정을 넘는 하루 시각
- 목록 `limit` 상한과 `cursor` 형식
- 응답에 상담사 `user_id`를 넣을지
- 가족 대리 예약 범위

## BE1을 확인하기 전에는 정하지 않음

- 사용자 테이블 이름, PK 컬럼, 자료형
- 그 테이블 마이그레이션 파일명과 번호
- 인증·승인 미들웨어의 경로와 호출 방법
- 승인 전 일정 설정을 막는 코드의 위치

BE2 FK와 라우트 공개는 그 확인 이후다. 마이그레이션 파일명 규칙 `NNNN_beN_description.sql`은 유지한다.
