BE2 담당 영역. 역할 문서와 docs/contracts.md를 기준으로 구현합니다. 공통 계약 변경은 담당자 리뷰가 필요합니다.

`availability.ts`는 상담 가능 시간의 순수 입력 검증만 담당합니다. DB·HTTP에 연결하지 않으며 업무 라우트를 열지 않습니다.

형식 검증은 `staff_id` UUID, 달력 날짜(`YYYY-MM-DD`), 오프셋 없는 하루 시각, `Z`로 끝나는 UTC 절대 시각을 구분합니다. 같은 날 시각 구간과 UTC 절대 구간은 종료가 시작보다 뒤여야 합니다. 같은 날 검사는 자정을 넘는 구간을 표현하지 않으며, 자정 넘김을 금지하는 정책이 아닙니다.

`interval.ts`는 `availability.ts`의 비교 함수만 사용해 두 구간의 끝점 순서를 13가지 관계로 반환합니다. 하루 시각 관계는 두 구간이 같은 하루라는 전제에서만 계산합니다. `meets`는 `overlaps`와 다르고, 이 관계는 예약 충돌이나 경계 포함 정책이 아닙니다.

요일 번호, 시간대 저장, 예외 시간의 종류와 우선순위, 맞닿은 구간을 중복으로 볼지는 합의 전입니다. 자정을 넘는 하루 시각은 나누거나 다른 시간대로 바꾸지 않습니다.

`appointment-transition.ts`는 호출자가 넣은 규칙으로 상태만 계산합니다. 예약 시각은 바꾸지 않고, 변경 요청의 수락 정책은 이 함수에 없습니다. 역할이 맞아도 본인 예약, 가족 연결, 상담사 승인, 담당자 배정을 검사하지 않으며 접근 권한을 보장하지 않습니다.

`appointment-conflict.ts`는 `relateUtcIntervals`로 같은 상담사 `user_id`와 같은 `person_id`를 각각 비교합니다. 점유 상태와 차단 관계는 호출자가 넘깁니다. 목록이 비어 있으면 충돌 없음이 아니라 정책 미설정입니다. `meets`는 호출자가 목록에 넣은 경우에만 차단됩니다.

`api-schema.ts`와 `api-contract.md`는 예약·가능 시간의 JSON 입출력 초안입니다. 인증된 `user_id`는 요청 본문에 넣지 않습니다. 라우트, DB, 상태 이름 목록은 아직 없습니다.

`consultation-record.ts`는 공통 `RecordVersion`을 수정하지 않고 새 버전으로만 추가합니다. 조회는 `consultation_id`와 `record_version_id`로 하며, 배열 순서를 최신 버전으로 보지 않습니다. 역할이나 검증되지 않은 접근 결정은 원문 조회를 허용하지 않습니다. 상세한 미확정 항목은 `consultation-record.md`에 있습니다.
