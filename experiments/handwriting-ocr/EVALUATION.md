# 실제 엔진 실행 결과 — 2026-10-29

**이 문서는 초기 합성 인쇄체 실험의 기록이다. 아래 표는 실제 손글씨 정확도가 아니다.** 후속 실제 사진은 `photo_eval.py`로 별도 평가하며 개인 사진·crop·정답·결과는 로컬 보고서에만 유지한다.

## 실행 조건

- Foundation 기준: `3dc0d8a4cabdca34b415d25004a5ba429c4c04ff`, PR #4 open 상태에서 후속 브랜치 사용.
- Windows x64 / Python 3.12 가상환경, 로컬 CPU. 실제 모델을 로드하고 이미지에서 텍스트를 추론했다. 외부 OCR API·유료 서비스·개인정보는 사용하지 않았다.
- 맑은 고딕 `malgun.ttf`로 만든 가상 문장 5개를 일반·6도 회전·밝기 45%로 변형한 15장. 각 엔진 2회씩, 총 90회 추론. 두 반복의 추출 텍스트는 세 엔진 모두 이미지별로 동일했다.
- 이미지·글꼴 SHA-256은 생성 manifest, 모델 URL·크기·해시는 `models-manifest.json`에 기록했다. 입력 이미지 내용이나 글꼴 파일을 Git에 추가하지 않는다.

## 정확도와 속도

공백·문장부호·개행을 포함한다. raw와 NFC 값이 이번 데이터에서는 같았다. 아래 값은 15개 합성 인쇄체 이미지에 대한 성공 추론 30회씩의 micro 오류율이며, 낮을수록 좋다.

| 엔진·설정 | 실행 성공 | raw/NFC CER | raw/NFC WER | 평균 추론 시간 |
|---|---:|---:|---:|---:|
| Tesseract 5.5.3, kor+eng, PSM 6 | 30/30 | 21.49% | 22.92% | 82.0ms |
| PaddleOCR 3.7.0, 한국어 PP-OCRv5 검출+인식 | 30/30 | 0.00% | 0.00% | 788.9ms |
| 한국어 손글씨 특화 ONNX, 단일 줄 인식 | 30/30 | 33.06% | 96.88% | 31.5ms |

PaddleOCR가 이 작은 인쇄체 세트에서는 정답과 일치했다. 이것은 실제 상담지·손글씨의 100% 정확도를 의미하지 않으며 운영 엔진 선정 근거로 충분하지 않다. Tesseract 결과의 마지막 개행도 CER에 포함했다. 특화 후보는 공백 누락이 많았으며 이를 제거해 수치를 개선하지 않았다. 단일 줄 인식기는 검출+인식 파이프라인과 기능 범위가 다르므로 손글씨 비교에서는 동일한 줄 crop과 전처리를 따로 설계해야 한다. PSM·전처리·글꼴에 따라 결과가 바뀔 수 있으며 위 설정 하나로 엔진 전체의 성능을 단정하지 않는다.

숫자 토큰 불일치는 Tesseract 2/30, Paddle 0/30, 특화 후보 4/30회였다. 키워드 경고는 각각 4/30, 0/30, 12/30회였다. 2회 반복을 포함한 횟수이며 서로 다른 이미지 개수와 혼동하면 안 된다. 키워드 빈도 차이는 의미 반전을 확정하는 판정이 아니다.

속도는 모델 로드 이후 추론 시간이다. cold load와 프로세스 시작을 포함한 서비스 지연이 아니다. 원본 JSON에 load_ms·batch_wall_ms·추론 후 RSS를 별도로 보존했다. RSS는 최대 메모리 사용량이 아니며 반복 간 속도와 메모리 수치는 달라질 수 있다.

## 실제 추출 예

정답: `최근 일주일 동안 식사를 하루 두 번 했다고 함.`

- Tesseract: `최근 일주일 동안 식사를 하루 두 번 했다고 함.\n`
- PaddleOCR: `최근 일주일 동안 식사를 하루 두 번 했다고 함.`
- 특화 ONNX: `최근일주일동안식사를하루두번했다고함.`

정답: `어제는 통증이 없었다고 이야기함.`

- Tesseract: `|는 = = |\n`
- PaddleOCR: `어제는 통증이 없었다고 이야기함.`
- 특화 ONNX: `어제는통증이없었다고 이야기함.`

실패한 글자를 임의로 복구하거나 정답으로 치환해 평가하지 않았다. 담당자 교정 데모에서는 OCR 결과와 별도로 교정본을 제출했다.

## 기존 서비스 통합

`demo.ts`에서 세 제공자 모두 사진 → 실제 OCR → 원문 조회 → 담당자 교정 version 1 → 확정 → 확정본 전달을 실행했다. 기존 Mock·권한 경계·버전 관리·확정 전 분석 입력 차단을 재사용한다. 공식 BE2 RecordVersion 생성, 자동 확정, 운영 서버 공개는 수행하지 않았다.

Python 모델 stderr의 Windows 네이티브 CP949 로그가 UTF-8 진단 해석을 깨뜨리는 문제를 발견해 benchmark의 통신을 바이트로 받고 stdout 프로토콜만 엄격한 UTF-8로 해석하도록 수정했다. 수정 후 전체 비교를 다시 실행했다. 평가 도구·프로세스 경계 테스트는 모델 없는 CI 테스트와 실제 로컬 추론을 구분한다.

## 재현 자료와 한계

- `evaluation-summary.json`: 원문·정답·실측 오류율·시간·모델명·이미지 해시를 포함한 약 36KB 기록. 전체 2회 반복 집계와 첫 반복의 개별 결과 45개를 담고, 이미지 payload·두 번째 반복의 중복 원문은 제외했다.
- `results/benchmark.json`, `results/benchmark.csv`, `results/report.html`: 로컬 전용 상세 결과. 이미지와 OCR 결과를 나란히 확인 가능하며 Git에서 제외한다.
- 실행 명령과 후보 출처·설치·모델 라이선스는 [README.md](./README.md)를 따른다.

최종 로컬 검증: Python 평가·안전성 테스트 18개 PASS, 백엔드 Vitest 100개 PASS(기존 88개 + 프로세스 어댑터 12개). pnpm 고정 잠금 설치·타입 검사·빌드·diff 검사와 Python 해시 잠금 설치·pip check도 통과했다. 기존 Node CI와 Python 실제 모델 추론은 별도 검증이다.
